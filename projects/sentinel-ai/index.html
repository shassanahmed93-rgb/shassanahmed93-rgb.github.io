THE EXPERIENCE

From suspicious request to deliberate action.

Designed around a practical truth: fraud prevention should make independent verification the easy next move.

⌕

Surface the cues

Transparent patterns identify pressure, secrecy, payment, credential, authority, and channel-shift signals in submitted text.

↗

Explain the result

Each matched signal is shown with its contribution. The score prioritizes review; it is not a probability or fraud verdict.

◫

Guide a safer response

Pause the action, use a known independent channel, and require a second approver for sensitive requests.

Submit

Analyst-provided message text enters the triage flow.

Understand

Review visible indicators and why they matched.

Verify

Reach the person through a trusted contact already on file.

Track

Create a case and record its human review status.

ENGINEERING WITH BOUNDARIES

Useful signals. Carefully stated limits.

What this prototype demonstrates

  • Responsive security-operations dashboard and demo case queue
  • Explainable text rules and safety workflow
  • Case management and local evaluation harness
  • Production-mode shared API key gate and rate limiting

What it does not claim

  • No validated audio, image, or video deepfake classifier
  • No live phone, email, SMS, meeting, or social integrations
  • Media intake does not analyze file bytes
  • Not ready for sensitive production data; requires full identity, tenant, and managed storage setup
BUILD NOTES

A security product prototype, built to be inspectable.

Architecture

Vanilla browser dashboard, Node API, explainable rule engine, and local demo case store.

Trust model

Advisory outputs, clear evidence labels, human review, and out-of-band verification guidance.

Next milestone

Select a licensed detector and evaluate it offline on consented, labeled, held-out samples before integrating media analysis.
